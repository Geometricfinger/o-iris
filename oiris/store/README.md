# oiris.store — C4
`db` (SQLite, versioned migrations, sealed JSON bodies, audit log), `migrations` (append-only), `sightings` (SightingLog with GPS policy, hash chain, export rounding, map pins + OSM attribution; SweepTimeline). **Depends on**: `oiris.security`, `oiris.guard`. Extend by appending a migration.

Resumable sighting chain (ADR-0066): `SightingLog` verifies the stored chain when it opens and continues it (`chain_status` "new", "resumed" with `unanchored_tail`, or "restarted" with a reason code, a new segment and a `chain_restart` audit entry; old rows are never rewritten). Anchors go to `chain_anchor` every 100 records or 60 s and at `close()`. Verdict changes, purge boundaries and restarts are chained side records in `audit_log` (`chain_verdict`, `chain_purge`, `chain_restart`; no sighting content). `verify_log(db, chain_key, verify_key)` checks the whole retained history and reports ok / edited / deleted / reordered / truncated / bad_anchor. Purge sighting rows through `SightingLog.purge` (or call `record_purge_boundary` first) so retention is not reported as deletion; `oiris/live.py` still has to wire `close()` and the purge path.
