# oiris.scores — score port (C1)
**Purpose**: one module per signal, `update(window) -> Score` with value/confidence in [0,1] and a health flag. **Inputs**: samples whose capability is in `inputs`. **Outputs**: `Score`. **Depends on**: `oiris.features`. Every call goes through `base.safe_update` (exceptions/NaN → FAILED).
**Extend**: implement the protocol, register under port `score`, map it to a family in `fusion/stack.SCORE_FAMILY`.

**Several scores in one family**: `fusion/stack.family_values` takes the family's value from its one score with the largest value × confidence (never a sum), and the family is active when any healthy score in it reaches `FAMILY_THRESHOLD` (0.5). More scores in a family therefore never add up, and never count as more than one family toward the ≥2-family alert rule.

## S_wifi (Wi-Fi access points, M-03, family `rf`, signature A4)
**Scores**: one AP scan (`ap_scan`). Each AP carries a coarse `class` set by the adapter from the raw BSSID before hashing (`features/rf.ap_class`): `camera_like` (OUI in the camera-vendor hint table), `randomized` (locally administered address) or `access_point`. Only APs at or above `WIFI_NEAR_DBM` (-55 dBm) can count, and only `camera_like` ones raise the value, by `WIFI_CAMERA_LIKE_WEIGHT` (0.5) each, capped at 1.0. An AP is normal furniture; a camera vendor's AP near the wearer is the useful hint. Confidence is `WIFI_CONFIDENCE` (0.4), below S_rf's 0.6, because an OUI is only a hint. Evidence holds counts only: `near_camera_like`, `near`, `randomized`. An empty or missing scan gives the no-data score.
**Never sees**: a BSSID, an OUI or a network name. The HMAC key is used only to count distinct APs within one scan; nothing is remembered across scans. Wi-Fi joins the `rf` family and adds no family, so an `rf`-only reading stays FYI.
