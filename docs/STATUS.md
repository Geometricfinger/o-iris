# Status: what is real, what is a stub

Version 0.1.0. "Real" = implemented and unit-tested headless (with simulated, replayed or faked inputs). "Observed live" = also run on the real device, with what was seen and when recorded in the row; that shows the code runs there, not that its signals are validated. "Untested on hardware" = code exists but has never touched the device. Nothing has been validated on real subjects. The same evidence, sorted into seen working, proven by automated checks, and built but not yet proven: [EVIDENCE.md](EVIDENCE.md).

## Needs hardware or real people (not done; not faked)
- Every hardware-dependent part built for the glasses, with its placeholders and the device check that would confirm it: [HARDWARE_READY_PROGRAM.md](HARDWARE_READY_PROGRAM.md).
- Real-device validation: Pi rig sensors, NoIR eye path thresholds, Android app on a phone (GPS fix, thermal view, front-camera eye, mic, BLE), BLE GATT pod↔phone/glasses radio path, Touch ID on a real Mac, ArUco on a real camera, glasses display brightness/legibility.
- Spoken-digit recogniser: the challenge logic is real; an offline ASR whose training data is verifiably commercial-OK has not been chosen.
- Trained fusion weights: need real golden data (hand-set prior until then).
- Real-subject tests: E-11/E-13/E-14 eye experiments, face matching on real faces beyond one manual live check (one consenting user, one Mac webcam, 2026-11-15); tests use synthetic frames only.
- Code signing/notarization: the macOS app is only ad-hoc signed; Developer ID signing and notarization need a paid Apple Developer ID (steps in docs/MACOS.md). Android release signing is the user's own key.
- Voice speaker-ID (ECAPA) and anti-spoof (AASIST): no checkpoint found whose **training data** is verifiably commercial-OK. Public ECAPA checkpoints (e.g. SpeechBrain, Apache-2.0 code) are trained on VoxCeleb: CC BY 4.0 metadata over third-party YouTube recordings whose copyright stays with the owners and whose speakers never consented. AASIST checkpoints are trained on ASVspoof corpora built from third-party speech data with edition-specific terms. Under the strict no-unclear-licence rule nothing is shipped; the model port stays pluggable (`S_voice` takes a spoof score from any model the user supplies).

## Open items (known gaps, not hidden)
- **Wi-Fi AP clock skew:** on macOS there is no beacon TSF, so the AP clock-skew method has nothing to measure. (The AP scans themselves are now scored by `S_wifi`.)
- **Clock sync not wired:** `oiris/link/timesync.py` and the pod `time_sync` op are built, but live mode neither sends `time_sync` nor converts remote timestamps before merging.
- **Sound direction not in the merge:** `oiris/features/doa.py` feeds only the voice-link direction; no adapter turns it into `sound` detections for the engine's spatial merge.
- **Power plan fields without a consumer:** `ir_illuminator`, `display_brightness_cap` and `radio_scan_interval_s` are computed and shown, but nothing in live mode applies them yet.
- **Monitor-mode check on macOS:** `guard/radio.py` queries `iw`, which macOS does not have, so on a Mac the check has nothing to query. O Iris never enables monitor mode itself.
- **Network guard scope:** live mode's guard covers Python sockets only; it does not police subprocesses or native code in drivers.
- **Apple Silicon only:** the macOS app's launcher is built for arm64 macOS 14+ and its bundled wheels are arm64; Intel Macs are not supported.
- **Motion thresholds are provisional:** the still/walking/fast thresholds and hold times in `modules/motion.py` come from typical head-worn walking traces and the simulated IMU; they must be measured on the glasses.
- **Speaker model not on Android:** only the voice-link rules are ported (`VoiceLink.kt`); the CAM++ model, the microphone capture and the announcer's player run only in Python.
- **Decisions deferred by ADR-0059** (until the glasses are chosen, with evidence from them): where the core runs (glasses, phone, pod or split; BLE bandwidth versus 16 kHz audio); the glasses gate (latency, legibility, battery, heat); moving enrolled templates between the owner's own devices; the wearer's own voice beyond the M-17 `self` marker; the choice of bystander light (the light, mute and capture interlock are built, ADR-0063; the glasses' own light needs its adapter); power and heat budgets (the policy is built, simulated and wired, ADR-0061; its thresholds, coefficients and budgets need measurements on the device). Code built for glasses is "built", not "working on glasses".
- **Retention purge scheduling:** `guard/retention.py` deletes rows older than `retention_days` (default 30). Live mode runs it when the store opens and every `retention_check_s` (default 3600 s), through the sighting chain's purge boundary; no other command (headless runs, the Pi rig) schedules it yet (ETHICS.md says the same).

## Resolved open items
- **Live sighting chain** (resolved by ADR-0066): the chain resumes across sessions, its anchors are persisted, and live mode closes and purges through it. Built and tested; not yet run in the app.
- **Wi-Fi AP scans not scored** (resolved): `S_wifi` scores near camera-maker APs as rf evidence. Built and tested with synthetic BSSIDs; not yet observed in the app.
