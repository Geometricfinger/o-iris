# Android companion app (Kotlin, minSdk 29)
**Purpose**: operator app and fallback detection node. **Inputs**: C1/C3 records over the Noise link (BLE GATT, `BleGattTransport`), local camera/BLE in fallback mode. **Outputs**: zone UI (P1–P5), voice tiers, encrypted sighting log. **Depends on**: AndroidX, SQLCipher, Mapsforge (see `dependencies.txt`), and the shared `schema/` JSON (packaged as assets).
Build: `cd android && gradle assembleDebug` (JDK 17, Android SDK 34). No INTERNET permission, `FLAG_SECURE`, no backups. Unsigned. See docs/STATUS.md for stubs.

Modules: `:core` (pure Kotlin: Noise_XX link byte-compatible with the pod, enrollment protocol/flow, alert visuals; `gradle :core:check` runs the JVM checks against `../tests/vectors`), `:app` (activities: Main, Map, Enrollment, Timeline · Review; CameraX glint capture and front-camera eye features; `ThermalView` with grayscale/colour toggle; GPS via `LocationSource`; optional `MicMonitor`; `BleGattTransport` to the pod). `:core` also holds `BleFraming`, `ThermalRender`, `EyeFeatures`, `ScanRateLimiter`, `GpsPolicy`, `MicLevel`, `Timeline`, `VoiceLink`, `GlassesHud`, `HudPainter`, `TimeSync`, `FusionCore` and `PowerGovernor`, all JVM-checked (2509 checks).

M-17 voice link on Android (`:core` `VoiceLink.kt`, ADR-0059): the decision rules (threshold, "unsure" margin, self, anti-spoof), the cosine score and voice template, the spoken-name rules with the shared `schema/vocabulary.json` banned words, the per-person repeat limit and the energy VAD. They are checked against `tests/vectors/voice_link.json`, which `scripts/make_android_vectors.py` generates from the Python code. Not on Android yet: the speaker model (sherpa-onnx has an Android build; the model is side-loaded later), the listener and the announcer's player. See docs/VOICE_LINK_MODULE_SPEC.md, "Android parity". C7 tokens are copied from `oiris/ui/design_tokens.json` into the APK assets at build time.

Glasses display (`:core` `GlassesHud.kt`): the glasses HUD (zones G1–G6) and the enrollment mini-guide are defined once as a display list of plain draw ops (`canvas`, `zone`, `text`, `shape`, `image`; fixed keys, see `OP_KEYS` in `oiris/ui/glasses.py`). Python's `display_list` / `enroll_guide_display_list` build it and the simulator's SVG (`render`, `oiris glasses-sim`) is one backend of it. `GlassesHud` builds the same list from the same state, the same design-token JSON (read through `Json.kt`) and the `schema/vocabulary.json` banned words: zone layout and `check_layout`, level shapes and colours, the alert-line word limit and vocabulary guard, no G2 pop-up while moving, health dots, the guide line with its reason truncation, the tick and the progress dots. Non-integer coordinates are rounded to `COORD_DECIMALS`; integer pixels stay integers, so ops match the vectors exactly, number types included. Checked against `tests/vectors/glasses_hud.json`, generated by `scripts/make_android_vectors.py` from the Python code. Drawing it: see "Drawing" below.

Clock sync (`:core` `TimeSync.kt`, planning for 360-degree coverage): cameras and microphones on several devices (glasses, phone, pod, helmet cameras) can only be merged once their stamps share one timeline, and each device stamps with its own monotonic clock (`Sample.t_mono_ns`). `TimeSync` is the same estimator as `oiris/link/timesync.py`. One NTP-style exchange gives offset = floor(((t1 - t0) + (t2 - t3)) / 2) (`Math.floorDiv`, so odd negative sums match Python `//`) and delay = (t3 - t0) - (t2 - t1). It keeps the last `MAX_SAMPLES` exchanges and uses the minimum-delay one. Once enough samples span enough time, it fits drift in ppm (Theil-Sen over the lowest-delay half). It refuses negative or too-long delays and out-of-range stamps, and reports `ok` / `unsynced` / `stale`. Timestamps are bounded to [0, 2^61) ns, so all Long arithmetic is overflow-free. Pod op over the Noise link: request `{"op":"time_sync","t0":<ns>}` (`TimeSync.request`), reply `{"ok":true,"t0":t0,"t1":<pod receive ns>,"t2":<pod send ns>}`, fed back with `addReply(reply, t0, t3)`, which also refuses a reply that echoes another t0. Checked against `tests/vectors/time_sync.json`, generated by `scripts/make_android_vectors.py` from the Python code (exchanges, the floor rule, asymmetric legs, refusals, best-of-N, drift, conversions, real pod replies). Not wired yet: the glasses/phone side will send `time_sync` every few seconds while linked (more often than `STALE_NS`), stamp t0/t3 with `SystemClock.elapsedRealtimeNanos()`, and convert every remote stamp with `remoteToHost(t, atHost)` before merging detections. While quality is not `ok`, remote detections stay unmerged rather than merged on a guessed clock.

## Drawing
The display list is drawn through an interface, so the drawing rules are checked on the JVM and only a thin adapter needs Android.
- `oiris/ui/paint.py` is the reference: `paint(display_list)` turns each op into the draw call that `glasses.to_svg` implies for it, in order. Calls: `frame` (size, background, opacity, font family), `rect`, `circle`, `polygon`, `polyline`, `text` (baseline, size, colour, weight, anchor) and `image` (the G3 placeholder). Zones draw nothing. A test parses the SVG and matches every call to its element, attribute by attribute.
- `:core` `HudPainter.kt` is the twin: the `HudCanvas` interface has one method per call kind, `HudPainter.paint(ops, canvas)` executes a `HudFrame.ops` list (`paintHud` takes `GlassesHud` ops), and `RecordingCanvas` records the calls. `Checks.kt` paints every case in `tests/vectors/hud_paint.json` (HUD states, each level still and moving, each cue direction, guide steps, hostile frames through `HudFrame.parse`) and must record exactly Python's calls. Dot radii and tick points use Python's float floor division (`pyFloorDiv`), as the SVG does. Unknown op or shape kinds and mistyped fields are skipped, never thrown.
- `:app` `AndroidHudCanvas.kt` implements `HudCanvas` on `android.graphics.Canvas`: hex colours via `HudPainter.colour`, the frame scaled uniformly into the view and centred, the frame opacity as paint alpha, text size, typeface and alignment from the anchor, round rects. `HudView.kt` is a `View` whose `onDraw` paints the current ops; it takes pod frames (`setFrame`), local lists (`setOps`) and the thermal frame for G3 (`setThermal`, pixels from `ThermalRender`). These two files are compiled only by CI (`scripts/build_all.sh`), because this Mac has no Android SDK; nothing here has run on a device or emulator.

What the real glasses will tune, with evidence from them (ADR-0059):
- display size and DPI: the logical 640 x 400 canvas (C7 tokens) is scaled to the panel, so the tokens' sizes and the canvas may change once its pixels and field of view are known;
- brightness: the frame opacity is today's token `default_brightness`; the cap should come from the power plan (`PowerGovernor`) and the ambient light;
- font: the token family (`sans-serif`) falls back to the system font; an open-licensed font with tabular figures may be bundled after a licence check.

## Parity
Spec E-27 asks for Python-Kotlin replay parity, so the glasses can run the core as Android code. Kotlin twins in `:core`, one for each Python module:
- `FusionCore.kt` is `oiris/fusion/stack.py` plus the C1 `Score` rules of `oiris/schema.py`. It has the family and signature maps (with `S_wifi` in rf), the threshold, the default weights, `family_values`, logit/predict, `fuse` (anomaly index rounded to 6 decimals half-even, as Python's `round` does) and the weights JSON with its fallback. An out-of-range or NaN value or confidence is clamped as Python does, not rejected. A score with an unknown health name is refused (Python's `Score()` raises). `advisory` (fallback node) is Kotlin-only and passed in by the caller.
- `PowerGovernor.kt` is `oiris/power/governor.py` and `duty.py`. It has the levels, the two axes with hysteresis, dwell and the stale rule, the reason codes, the Android thermal-status mapping, config validation with Python's error strings, the per-level plans and their order rule, `FrameGate` and `ListenDuty`. Time comes from each reading, an explicit `now` or an injected clock.
- Earlier twins: `TimeSync.kt`, `VoiceLink.kt`, `GlassesHud.kt`, `LinkOps.kt` and the enrollment flows (see above).

How the vectors keep them equal: `scripts/make_android_vectors.py` runs the real Python code and writes `tests/vectors/*.json` (here `fusion.json` and `power_governor.json`). `Checks.kt` replays every vector in Kotlin, and the constants too. It runs in `gradle :core:check`, 2509 checks. Floats agree within `FLOAT_TOL` (1e-6); levels, reasons, strings and booleans must match exactly. Python tests (`tests/test_fusion_vectors.py`, `tests/test_power_vectors.py`) fail when a vector file is stale. A change on either side therefore fails until both sides agree. `android/app` `Fusion.kt` keeps its small API (`Score`, `Level`, `Fusion.fuse(scores, fallbackNode)`) and delegates to `FusionCore`, so the app now fuses exactly as Python does (`S_wifi` counts as rf; a suppressed result still lists its active families).
